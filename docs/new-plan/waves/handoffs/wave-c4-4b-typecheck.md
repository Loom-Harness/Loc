## 2. The shared builders (the whole point of the packet)

The wave log's own diagnosis held: two thirds was one shape. The fix is
**naming the VARIANT instead of the union**, so a builder's result can be
spread and extended.

### `test/_helpers/ir-builders.ts` (new)

- `ExprOf<K>` / `StmtOf<K>` / `TypeOf<K>` / `WorkflowStmtOf<K>` — `Extract` one
  arm of an IR union by its discriminator. This alone kills the TS2322/TS2353
  half: a builder annotated `ExprIR` returns a UNION, so
  `{ ...thisProp("total"), type: MONEY }` is "every arm plus `type`", which
  excess-property checking rejects for the arms that do not declare it.
- Type nodes: `primType`, `arrayType`, `STRING_T` / `INT_T` / `DECIMAL_T` /
  `MONEY_T` / `BOOL_T`.
- Expression nodes: `litExpr`, `refExpr`, `paramRef`, `thisPropRef`,
  `memberExpr`, `matchExpr` (which supplies the REQUIRED `variantArms: []` the
  boolean form still carries).
- Structural: `deployableIR(over?)`, `systemIR(over?)` — full-shape with empty
  defaults, replacing `{ … } as SystemIR` partial casts. A new required field
  on either interface now lands here once instead of in every suite.

Every builder returns exactly the object literal the hand-written fixture
spelled, so swapping one in cannot move a generated byte.

### `test/_helpers/diagnostics.ts` (new)

- `LspDiagnostic` — derived off `LangiumDocument["diagnostics"]`, so the test
  tree takes no undeclared direct dependency on `vscode-languageserver-types`.
  **`langium` does not export `Diagnostic`**; eight files imported it from
  there, so every diagnostic in those suites was `any`. Fixing
  `test/_helpers/parse.ts`'s import is what surfaced the next item.
- `diagText(d)` — LSP `message` is `string | MarkupContent`; Langium only ever
  produces the string form. 98 errors across 26 files were this one read.
- `diagCodes(diags)` — the IR side's `code?: string`, with the repo's existing
  `?? ""` convention applied once.
- `lspCodes(diags)` — replaces **seventeen** byte-identical private copies of
  `const codesOf = (diags: { code?: string }[]) => …`, a parameter type no real
  `Diagnostic` satisfies (LSP `code` is `integer | string`).

### `test/_helpers/ast.ts` (new)

- `contextMembersOf(model)` — replaces fourteen copies of
  `.members.flatMap((m) => ("members" in m ? m.members : []))` chained twice.
  The `in` narrowing yields a union of five member arrays, so every downstream
  `.find` saw `unknown` — and the chain silently returns the WRONG level for a
  root shape it does not match (see §4). Descends all three roots: bare
  `context`, `system → context`, `system → subdomain → context`.
- `nodeName(node)` — the `(n as { name: string }).name` read TS rejects on an
  `AstNode`, in one place instead of fifty.

### `test/_helpers/ir.ts` (extended)

- `enrichedContexts` / `enrichedAggregates` — the enriched-brand-preserving
  twins of `allContexts` / `allAggregates` (see §5, hand-off H1).
- `systemContexts(sys)` — `SystemIR` has no `contexts` field (see §4).
- `reEnrich(model)` — the idempotency double-application (see §5, hand-off H2).

### `test/behavioral/registers.d.mts`, `mix-retry.d.mts` (new)

The behavioural registers are plain `.mjs` (the runners are unbuilt node
scripts). Four TypeScript consumers imported them and every binding was `any` —
exactly how a register lookup returns the wrong shape unnoticed.

## 5. Hand-offs OUTSIDE the fence (with recipes)

Nothing under `src/**` was edited. Three type-level improvements belong there
and are handed off:

**H1 — `allContexts` / `allAggregates` erase the enriched brand.**
`src/ir/types/loom-ir.ts:4018,4028` declare `LoomModel → BoundedContextIR[]`, so
every caller starting from an `EnrichedLoomModel` silently loses
`eventSubscriptions`, the enriched `aggregates`/`valueObjects`, … and reads
them back off a type that does not declare them. Recipe: add an overload pair

```ts
export function allContexts(loom: EnrichedLoomModel): EnrichedBoundedContextIR[];
export function allContexts(loom: LoomModel): BoundedContextIR[];
export function allContexts(loom: LoomModel): BoundedContextIR[] { … }   // unchanged body
```

and the same for `allAggregates`. Then delete `enrichedContexts` /
`enrichedAggregates` from `test/_helpers/ir.ts` and re-point their 10 call
sites. Repro: `const ctx = allContexts(await buildLoomModel(src))[0]!;
ctx.eventSubscriptions` → `TS2339`.

**H2 — `enrichLoomModel` cannot express its own idempotency.**
`src/ir/enrich/enrichments.ts:110` takes `RawLoomModel`, whose
`__phase?: "raw"` brand is incompatible with the `"enriched"` it stamps, so
`enrich(enrich(m))` — which four suites pin as a property — has no spelling that
keeps the brand. Recipe: widen the parameter to
`RawLoomModel | EnrichedLoomModel`; then delete `reEnrich` from
`test/_helpers/ir.ts` and re-point its four call sites.

**H3 — `scripts/{pr-gate,quality-delta,ledger-counts}.mjs` have no
declarations.** Three `test/system` suites import them by name and every
binding is `any`; they are suppressed at the import with `@ts-expect-error` and
the reason. All three are fully JSDoc-typed, so the fix is a `.d.mts` beside
each (or a `checkJs`-scoped project). The directive is **self-ratcheting**: the
moment a declaration lands, TS2578 "Unused '@ts-expect-error' directive" fires
and the suppression must be deleted. `scripts/**` is 4a's fence, hence a
hand-off rather than an excursion.

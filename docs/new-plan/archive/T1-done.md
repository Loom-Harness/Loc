## M-T1.4 — Frontend component parity: extern (Angular + HEEx + Vue/Svelte) and WALKED components (Angular + Feliz) — `done` (extern verified 2026-07-16; walked Angular+Feliz 2026-08-11) · **M** · P1
**The `extern` half was done; the WALKED half was silently missing on two targets.** A user-declared (non-`extern`) `component TierBadge(label: string, level: int) { body: … }` produced **no output at all** on Angular and Feliz — only the extern flavour was wired — so the name never entered the walker's `userComponents` map and every use site rendered `<!-- unknown layout component: TierBadge -->` / `(* unknown layout component: TierBadge *)`. Declaration and use vanished together: the last two rows of the `KNOWN_DEGRADATIONS` ratchet in `test/generator/_walker/render-degradation.test.ts`, **now deleted with the fix** (the ratchet fails on a stale entry, so deletion is part of the fix).

- **Angular** (`src/generator/angular/components-emit.ts`) — one standalone `@Component` class per walked component at `src/app/components/<Name>.ts`, assembled by the SAME shell that assembles a page (`renderAngularPage` gained a `componentMode`), so state → `signal()`, `derived` → `computed()`, named `action`s → methods, api-read hoists, Reactive `FormGroup`s and the i18n / `FORMAT_HELPERS` / `String` / `Decimal` member lifts all come along instead of a second half-featured assembler. Params bind as plain `@Input()` fields (bare template reads, matching a bound route param) — deliberately NOT `required: true`, which would turn a call site that omits an arg into an Angular-only NG0950 throw where the other five frontends render `undefined`. `src/app/components/` (not react's `src/components/`) is a SIBLING of `src/app/pages/`, so every relative path the shell bakes in resolves unchanged from either. Call sites keep the extern path's `NgComponentOutlet` form (Angular has no PascalCase tag; the outlet is selector-free), so only the import path distinguishes the flavours.
- **Feliz** (`src/generator/feliz/component-emit.ts`) — one F# function of its props record per component (`let TierBadge (props: {| label: string; level: int |}) = …`, USED params re-bound as locals), declared in a nested `Components` module (immediately `open`ed) ahead of the page views, on the channel the hoisted `DataGrid` child already rides (F# is order-sensitive; Feliz has no per-component file). The single anonymous-record parameter is what keeps ONE call form for both flavours — the extern seam's `Name {| … |}` already matches it. An aggregate / value-object param is typed from the app's **emitted** wire records (read off the rendered domain records), so a record this app doesn't emit is never named. **Why the module** (measured, not assumed): `App.fs` is one F# module and Fable maps each member to a same-named JS binding, so a top-level `let Product` beside the emitted `type Product` is a hard `error FABLE: Cannot have two module members with same name` — and nothing stops a user naming a component after an aggregate, a `<X>Form`, a grid child, or `Model`/`Api`/`View`. Enumerating those names would duplicate every naming decision the emitter makes; the module makes the collision impossible instead, and the `open` keeps call sites bare (a PascalCase value beside a same-named type/module is unambiguous in F#).
- **Deferred, on purpose, and still visible in the ratchet** — never a dangling reference: Angular defers a `slot`/`action(T)` param (`ngComponentOutletInputs` sets inputs; it has no content-projection channel), any body reaching the shared React-shaped form/mutation sinks, and an api read whose ARG reads an `@Input()` (a read hoists as a class-FIELD initializer, which runs before Angular sets inputs — it would compile and then throw at construction; an arg-less read and a reactive find are unaffected and supported). Feliz additionally defers `state {}` / `derived` / named `action`s / reads / forms, plus a mechanical backstop that drops any component whose rendered F# reaches for `model`/`dispatch`: a Feliz app is ONE Elmish program, so per-component state is a genuine MVU design question (sub-models), not a rendering gap. A deferred component keeps the give-up comment at its call site, so the gate keeps naming it.
- **Verification** — mutation-proved (both emitters stubbed to emit nothing: 19 of the 23 new per-target walker tests fail, plus the ratchet's per-target scan reporting "NEW degradation(s)" on both targets; the 4 that stay green are the deferral pins, which assert absence). Real toolchains, not just IR: `ng build` (Angular 22, `strictTemplates`) green over a showcase carrying four component shapes — scalar inputs, an aggregate-typed input, a stateful signal/computed/action component, and a READ-bearing one whose TanStack query hoists as a class field (all now in the `generated-angular-build` showcase case); `dotnet fable` + `vite build` green on the `generated-feliz-build` showcase, which grew a scalar-props `PriceTag` and a wire-record `ProductLine`, plus a headless-chromium check that both actually RENDER at runtime.

## M-T1.21 — Flutter money is broken end-to-end: every read crashes, every submit is rejected — `done` (2026-08-30) · **M** · P1 ⭐ compiles green, dies on the first list page

Found 2026-08-23 by the numeric-types audit ([F1](../../audits/numeric-types-audit-2026-08-23.md)). Money crosses the wire as the RS-12 fixed-scale string (`"12.5000"`), but the generated Dart decodes it `(json['price'] as num).toDouble()` (`dartFromJson`, `src/generator/flutter/dart-types.ts`) — a runtime `type 'String' is not a subtype of type 'num'` on every list/detail/projection/dashboard read of a money-bearing model. Forms go wrong in the other direction: `double.tryParse` submits a JSON **number** (`src/generator/flutter/forms-emit.ts`), which every backend's string-typed money field rejects with 422/400.

**Why every existing gate is green.** `generated-flutter-build.yml` is compile-only and its embedded fixture declares `price: int` plus a hand-rolled `valueobject Money { amount: int }` — the `money` *primitive* never reaches Flutter in any gate. Worse, the wrong decode is test-**pinned** in `test/generator/flutter/dart-model.test.ts`.

**The fix** (proposed default, overridable in draft-PR review): money in Dart is the wire **string** with typed helpers — never `double` (which also caps money at ~15–17 significant digits against `NUMERIC(19,4)`). Decode takes the string as-is; forms keep text input and submit the string; display parses for formatting only. Re-pin `dart-model.test.ts` to the correct shape.

**Verification when it lands.** The flutter CI fixture gains a money-primitive field (the F18 witness this class never had), the re-pinned suite is mutation-proved by restoring the `as num` decode, and M-T9.38's runtime leg is the eventual end-to-end proof.

**Landed 2026-08-30.** In two steps, and the second is the one this mission is about. #2637 removed the CRASH by parsing the wire string into a `double` and re-formatting it with `toStringAsFixed(4)` — no more `String is not a subtype of num`, no more 422, but money still lived inside a binary float (~15–17 significant digits against `NUMERIC(19,4)`, re-quantized on every read→write round trip). The retype completes it: `money` in Dart IS the wire string, with a generated `lib/money.dart` (`LoomMoney`, BigInt scaled units) behind arithmetic, comparison and the six intrinsics; forms submit the typed text validated against the wire's own grammar; display/chart parse only to format. `decimal` stays a JSON number / Dart `double` — the control in every re-pinned test. One new optional walker seam (`exprMoneyBinary`) keeps every other target byte-identical. The showcase leg of `generated-flutter-build.yml` now carries a money primitive, an operation form, a charted money projection column, a money state cell and an intrinsic — the F18 witness — and `flutter analyze` on the generated app caught a real dangling-import bug before merge. Remaining: the JS-side `Table` money sort (M-T1.24 family) and M-T9.38's Flutter runtime leg.

## M-T1.26 — `Image` / `Avatar` `src:` and `alt:` are still on the pre-A12 helper — a computed value is silently dropped, a param ref emits a template literal — `done` (Wave 1, #2752: react/svelte/feliz/flutter via `_walker/primitives/text.ts`, vue/angular via the pack templates + two `_packs/loader.ts` helpers; pinned by `test/generator/_walker/image-avatar-attr-cross-target.test.ts`) · **S** · P2

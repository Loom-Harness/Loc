## 3. Rules every wave agent follows

§3/§3a of [`improvement-waves-2026-09.md`](improvement-waves-2026-09.md) apply verbatim (fresh `main` then verify the row; claim inside the wave PR; tree fences; silent → honest or fixed; mutation-prove and name the assertion; seam-first when ≥ 3 targets; byte-identical gate on refactors; local gates before hand-off; close the loop in docs; one PR per wave, at most one push per day, rebase only on a real conflict). Nine additions, each paid for once in the window:

10. **Prove framework-enforced behaviour on a booted app.** If the narrowing is enforced by pydantic, Hibernate Validator, ASP.NET model binding, Ecto or a Postgres constraint, `npm test` cannot see it — the proof is a `curl` against a generated backend on a real Postgres (§100–§105; the `generated-stack-verifier` skill). A PGlite harness with no foreign keys is not a Postgres.
11. **Sweep over the axis the bug travels on.** A gate for an import obligation, an annotation placement or a wire alias asserts over *every* emitted module / route signature of the project, with a vacuity guard that the fixture actually produces the shape (§104/§105).
12. **A constant read from the emitter verifies consistency, not correctness.** At least one assertion per contract takes its expected value from outside both the emitter and the test — the database's own error, the framework's own response, the OpenAPI the backend publishes (§100).
13. **The corpus must contain the shape.** A fix that adds a gate adds the `.ddd` fixture in the same wave (separate commit, per CLAUDE.md), and the fixture is extended until every emitter arm the mutation names goes red (§104's second bug).
14. **Re-sync before the flip.** Run the full fast suite on the folded tree *after* the last `git merge origin/main`, not before (§107); a `loom.*` code minted in the PR carries its `code-docs.ts` anchor in the same commit.
15. **Never re-run a red check to retest against a fixed base** — merge `origin/main` into the head so GitHub computes a new merge commit (§108); `git merge-tree --write-tree` before resolving any reported conflict (§109).
16. **Two optional seams at one insertion point: pin the order with the reason inline** (§110).
17. **A diagnostic collected and reported only on success is not a diagnostic** — harnesses append collected page/console errors to the thrown error (§111).
18. **`npx tsc -b` is not the typecheck** — `node scripts/test-typecheck.mjs` is the gate for `test/**` (§112); a packet that adds a test file runs it.

**Model.** Every packet below is an **Opus** agent — the owner's instruction for this programme, and the right call for a plan whose remaining rows are cross-backend, security-shaped, or need a ruling; the mechanical work that Sonnet could do (status moves, ledger closes, doc rewrites) is folded into the packet whose code it describes rather than split out. One **Opus coordinator per wave** owns the wave PR, the fold order, the byte-identical re-checks on the folded tree, and the single daily push. Every agent gets the two-line RUNBOOK kickoff plus the packet block (§6).

**Wave shape.** One draft PR per wave (two where a CI-workflow change must land alone) — **except C2, which ships one PR per target tree** (2a…2j, grouped two or three where trees are small): #2770 was rebased six times in a week and left #2778 dirty behind it, and C2 is strictly larger than #2770, so a self-conflicting ten-tree fold would spend more CI in rebases than the split spends in parallel runs. The wave stays the claim and coordination unit either way. Packets on `claude/<wave>-<packet>` sub-branches (git refuses `wave/packet` while `wave` exists). Waves C1–C4 are tree-fenced against each other and may run concurrently once C0 is merged; C3 is test-only by construction. Sizes are Opus-agent-weeks at the observed ~1 packet-row per 2–4 hours, and every wave has run long in this repo — budget the queue, not the calendar.
